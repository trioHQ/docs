---
title: "Events"
description: "Every event category Trio can send to a V2 webhook, with the types of each category and an example payload."
---

Each notification carries a `category` and a `type` in the envelope described in [Content and structure](/v2/webhooks/content-and-structure). The `category` and `type` of a notification are the status of the V2 resource it reports, so route on them together, for example `in_document.settled`.

This page lists the events of a `v200` webhook. A `v100` webhook receives the same events translated to the V1 names: `collecting_document`, `payment_document`, `virtual_account_id` and no `stages`. See [Choose the payload version](/v2/webhooks/introduction#choose-the-payload-version).

## Categories and types

| Category | Types | Meaning |
| --- | --- | --- |
| `in_document` | `created`, `confirmed`, `kyc`, `settled`, `failed` | A cash-in document (a payment you received) changed state. |
| `in_document_refund` | `created`, `confirmed`, `settled`, `failed` | A refund of a payment you received changed state. |
| `out_document` | `created`, `confirmed`, `settled`, `failed` | A cash-out document (a payment you sent) changed state. |
| `out_document_refund` | `created`, `confirmed`, `settled`, `failed` | A refund of a payment you sent changed state. |
| `transfer_document` | `created`, `settled`, `failed` | A transfer between your bank accounts changed state. |
| `recurrence` | `created`, `approved`, `rejected`, `expired`, `cancelled` | A Pix Automático recurrence changed state. |
| `recurrence_request` | `created`, `sent`, `received`, `rejected`, `accepted`, `expired`, `cancelled` | A Pix Automático recurrence request changed state. |
| `recurrence_collection` | `created`, `active`, `settled`, `expired`, `rejected`, `cancelled` | A collection of a Pix Automático recurrence changed state. |
| `recurrence_collection_attempt` | `requested`, `scheduled`, `settled`, `cancelled`, `rejected`, `expired`, `failed` | An attempt to settle a collection changed state. |
| `boleto` | `created`, `confirmed`, `updated`, `settled`, `protested`, `refunded`, `failed`, `cancelled` | A boleto you issued changed state. |
| `pledged_advance_request` | `created`, `approved`, `rejected`, `canceled`, `allocated` | A pledged advance request changed state. |
| `entity` | `in_review`, `approved`, `rejected` | The compliance status of an entity created through onboarding changed. This category has a single format and is sent to webhooks of both payload versions. |

<Note>
  Coming from V1? Four categories were renamed in V2: `collecting_document` is now `in_document`, `collecting_document_refund` is now `in_document_refund`, `payment_document` is now `out_document` and `payment_document_refund` is now `out_document_refund`. Inside `data`, `virtual_account_id` is now `bank_account_id`, `collecting_document_id` is now `in_document_id` and `payment_document_id` is now `out_document_id`. The `initiation_document` and `pix_biometrics_enrollment` categories are not sent to `v200` webhooks.
</Note>

## Boleto

Category `boleto`: a boleto you issued. See [Create a boleto](/v2/guides/boleto/create-boleto) for the flow that produces these events.

| Type | Meaning |
| --- | --- |
| `created` | A boleto was created. |
| `confirmed` | A boleto was confirmed. |
| `updated` | A boleto was updated. |
| `settled` | A boleto was paid. |
| `protested` | A boleto was protested. |
| `refunded` | A boleto was refunded. |
| `failed` | A boleto failed. |
| `cancelled` | A boleto was cancelled. |


## In document

Category `in_document`: a cash-in document, a payment you received. See [Cash-in](/v2/guides/receivables/cash-in) and [Document lifecycle](/v2/guides/pix/document-lifecycle).

| Type | Meaning |
| --- | --- |
| `created` | An in document was created. |
| `confirmed` | An in document was confirmed. |
| `kyc` | An in document is waiting for a KYC check. |
| `settled` | An in document (cash-in) was successfully received and registered in the system. |
| `failed` | An in document (cash-in) was received but could not be processed and was refused. |

## Entity

Category `entity`: sent whenever the compliance status of an entity created through [onboarding](/v2/api-reference/banking-api/onboarding/create) changes. See the [Onboarding guide](/v2/guides/onboarding-guide).

| Type | Meaning |
| --- | --- |
| `in_review` | The entity is under compliance analysis. When applicable, each representative includes a `liveness_link` for the required biometric/liveness check. |
| `approved` | The entity has been approved by compliance and is ready to operate. |
| `rejected` | The entity has been rejected by compliance. The `reason` field describes why. |
