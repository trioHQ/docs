description: Guide to create boleto
---

Create a boleto receivable by defining the charge, payer, payment conditions, and boleto configuration.

This guide focuses on the **request body** of `POST /v2/in/boletos` and explains how each part of the boleto works, especially the payment rules such as discounts, fines, and interest. The full field list is in the [Create boleto](/v2/api-reference/banking-api/receivables/boletos/post) API reference.

> All examples use fictitious data.

# Request body

A boleto request is mainly composed of:

```text
Boleto
│
├── Charge
│   ├── amount
│   ├── description
│   └── external_id
│
├── Payer
│   └── counterparty
│
├── Payment conditions
│   └── due_detail
│       ├── due_date
│       ├── discount
│       ├── fine
│       └── interest
│
├── Boleto configuration
│   ├── bank_account_id
│   ├── expiration_date
│   ├── invoice_type
│   └── wallet_type
│
└── Optional
    ├── notes
    ├── splits
    ├── options
    └── merchant
```

The following example shows a complete boleto:

```json
{
  "description": "Mensalidade agosto",
  "amount": 10000,
  "external_id": "boleto-demo-2026-001",
  "bank_account_id": "019f0000-1234-5678-9abc-000000000001",
  "counterparty": {
    "name": "Maria Silva",
    "state": "SP",
    "address": "Rua das Flores, 100",
    "city": "Sao Paulo",
    "tax_number": "12345678901",
    "district": "Centro",
    "postal_code": "01001000"
  },
  "expiration_date": "2026-10-30",
  "invoice_type": "invoice",
  "wallet_type": "book_entry_electronic_bloquete",
  "notes": null,
  "due_detail": {
    "due_date": "2026-08-17",
    "fine": {
      "value": 150,
      "calculation_type": "percentage"
    },
    "interest": {
      "value": 300,
      "calculation_type": "monthly_fee"
    },
    "discount": {
      "fixed_until_due": {
        "amounts": [
          {
            "value": 500,
            "date": "2026-08-16"
          }
        ],
        "calculation_type": "percentage"
      }
    }
  }
}
```

This example represents a **R$ 100.00** boleto with:

* due date on August 17, 2026;
* 5% discount until August 16;
* 1.5% fine after the due date;
* 3% monthly interest after the due date.

Every payment rule inside `due_detail` follows the same convention: a rule calculated as a monetary amount sends `amount` in **cents**, and a rule calculated as a percentage sends `value` in **basis points** (100 = 1%). The sections below show both forms for each rule.

> **Migrating from V1?** In V1 the percentage of a rule was also sent in the `amount` field. In V2 percentages move to `value`; the numbers themselves do not change (`500` was and still is 5%).

# Charge

The charge section defines what is being collected and how your system identifies the boleto.

## `amount`

Defines the boleto amount.

The value is sent in **cents**.

```json
"amount": 10000
```

means:

```text
R$ 100.00
```

Examples:

```text
1500  → R$ 15.00
10000 → R$ 100.00
402   → R$ 4.02
```

This is the original amount of the boleto. Discounts, fines, and interest are payment conditions that can change the amount the customer must pay depending on when the boleto is paid.

The amount cannot be changed after the boleto is created; to charge a different amount, [recreate the boleto](#after-creation).

---

## `description`

A short description of the charge, up to 25 characters.

```json
"description": "Mensalidade agosto"
```

Use it to identify what the customer is being charged for.

For example:

```text
Mensalidade agosto
Pedido 12345
Plano Premium
Serviço de consultoria
```

---

## `external_id`

An identifier generated by your own system, up to 40 characters.

```json
"external_id": "boleto-demo-2026-001"
```

It does not replace the Trio boleto ID. Instead, it allows your system to associate the boleto with an internal record.

For example:

```text
Your system
    │
    ├── Order: 12345
    ├── Invoice: 2026-08-001
    └── external_id: boleto-demo-2026-001
                              │
                              ▼
                         Trio boleto
```

This is particularly useful for reconciliation.

# Payer

The `counterparty` object identifies the person or company that will pay the boleto.

```json
"counterparty": {
  "name": "Maria Silva",
  "state": "SP",
  "address": "Rua das Flores, 100",
  "city": "Sao Paulo",
  "tax_number": "12345678901",
  "district": "Centro",
  "postal_code": "01001000"
}
```

The fields describe the payer:

| Field         | What it represents                              |
| ------------- | ----------------------------------------------- |
| `name`        | Payer's name                                    |
| `tax_number`  | CPF or CNPJ, digits only (11 to 14 digits)      |
| `address`     | Street and address number                       |
| `city`        | Payer's city                                    |
| `state`       | Brazilian state, as a two-letter code (`SP`)    |
| `district`    | Neighborhood                                    |
| `postal_code` | CEP, 8 digits with no separator                 |

All seven fields are required. The information should correspond to the actual payer associated with the boleto.

In the response, the payer comes back as a `counterparty` object with the `id` Trio assigned to it.

# Payment conditions

The `due_detail` object is where the main payment rules are configured.

```json
"due_detail": {
  "due_date": "2026-08-17",
  "discount": {},
  "fine": {},
  "interest": {}
}
```

It controls what happens **before, on, and after the due date**.

```text
                 BOLETO

          Before due date
                 │
                 ▼
             Discount
                 │
                 ▼
             Due date
                 │
        ┌────────┴────────┐
        │                 │
      Payment          Late payment
                          │
                    ┌─────┴─────┐
                    ▼           ▼
                  Fine       Interest
```

Only `due_date` is required. `discount`, `fine` and `interest` are optional, and in the response each one is present only when it was set.

# Due date

## `due_detail.due_date`

Defines the date on which the boleto becomes due.

```json
"due_date": "2026-08-17"
```

In this example:

```text
Due date = August 17, 2026
```

The due date is the reference point for the payment rules.

Before this date, a discount may apply.

After this date, the configured fine and interest may apply.

# Discounts

A discount is a benefit given to the customer for paying before the due date.

Discounts are configured inside:

```json
"due_detail": {
  "discount": {}
}
```

The API supports two discount models:

```text
fixed_until_due
per_day_antecipated
```

Set **only one** of them in a boleto.

## Fixed discount before the due date

Use `fixed_until_due` when you want to define a specific discount for one or more dates before the due date.

Example:

```json
"discount": {
  "fixed_until_due": {
    "amounts": [
      {
        "value": 500,
        "date": "2026-08-16"
      }
    ],
    "calculation_type": "percentage"
  }
}
```

Here:

```text
value = 500
calculation_type = percentage
```

means **5%**.

For a R$ 100.00 boleto:

```text
Original amount       R$ 100.00
Discount                    5%
Discount value         R$   5.00
Amount to pay          R$  95.00
```

The discount is available until the configured date, which is the last date on which it applies.

### Different discounts for different dates

You can define multiple discount dates:

```json
"fixed_until_due": {
  "amounts": [
    {
      "value": 500,
      "date": "2026-08-14"
    },
    {
      "value": 300,
      "date": "2026-08-15"
    },
    {
      "value": 100,
      "date": "2026-08-16"
    }
  ],
  "calculation_type": "percentage"
}
```

This represents:

```text
Aug 14 → 5% discount
Aug 15 → 3% discount
Aug 16 → 1% discount
Aug 17 → Due date
```

This model is useful when the discount becomes smaller as the due date approaches.

---

## Discount per anticipated day

The `per_day_antecipated` model calculates the discount based on how early the customer pays.

Example:

```json
"discount": {
  "per_day_antecipated": {
    "value": 100,
    "calculation_days": "calendar",
    "calculation_type": "percentage"
  }
}
```

Here:

* `value` (or `amount`) defines the discount granted per day paid in advance;
* `calculation_type` defines whether that discount is an amount or a percentage;
* `calculation_days` defines how days are counted.

The available day calculation modes are:

```text
working
calendar
```

Use `working` for working days or `calendar` for calendar days.

---

## Discount calculation type

The discount can be calculated as:

```text
amount
percentage
```

### Percentage

```json
"calculation_type": "percentage"
```

The rule takes `value`, a percentage in basis points (100 = 1%).

For example:

```json
"value": 500
```

means:

```text
5%
```

### Fixed amount

```json
"calculation_type": "amount"
```

The rule takes `amount`, a monetary amount in cents.

For example:

```json
"amount": 500
```

means:

```text
R$ 5.00
```

# Fine

The fine is a penalty applied when the boleto is paid after the due date.

It is configured with:

```json
"fine": {
  "value": 150,
  "calculation_type": "percentage"
}
```

There are two calculation types:

```text
amount
percentage
```

## Percentage fine

```json
"value": 150,
"calculation_type": "percentage"
```

represents a **1.5% fine**.

For a R$ 100.00 boleto:

```text
Original amount: R$ 100.00
Fine:                 1.5%
Fine amount:      R$   1.50
```

## Fixed fine

```json
"amount": 150,
"calculation_type": "amount"
```

represents a fixed monetary fine of **R$ 1.50**.

The important distinction is:

```text
percentage → value, in basis points of the boleto amount
amount     → amount, a fixed monetary value in cents
```

# Interest

Interest is another charge that can apply after the due date.

It is configured with:

```json
"interest": {
  "value": 300,
  "calculation_type": "monthly_fee"
}
```

The available calculation types are:

```text
daily_rate
monthly_fee
exempt
bank_control
```

Each type determines how the interest value is interpreted, and which field carries it:

```text
daily_rate   → amount (cents per day)
monthly_fee  → value (basis points per month)
exempt       → neither
bank_control → neither
```

## Daily interest

```json
"interest": {
  "amount": 10,
  "calculation_type": "daily_rate"
}
```

The interest is a fixed amount charged per day overdue. Here `10` means **R$ 0.10 per day**.

## Monthly interest

```json
"interest": {
  "value": 300,
  "calculation_type": "monthly_fee"
}
```

Here:

```text
300 + monthly_fee
```

represents **3% per month**.

For a R$ 100.00 boleto, the configured monthly interest rate is:

```text
3% per month
```

## Exempt from interest

```json
"interest": {
  "calculation_type": "exempt"
}
```

Indicates that interest is exempt. Do not send `amount` or `value` with this type.

## Bank-controlled interest

```json
"interest": {
  "calculation_type": "bank_control"
}
```

The interest calculation follows the bank-controlled configuration. Do not send `amount` or `value` with this type.

# Fine vs. interest

Fine and interest are different concepts.

### Fine

A penalty for paying after the due date.

```text
Late payment
     │
     └── Fine
```

### Interest

A charge related to the period the payment remains overdue.

```text
Late payment
     │
     └── Interest
          │
          └── Based on the configured rate
```

They can be configured together.

For example:

```json
"fine": {
  "value": 150,
  "calculation_type": "percentage"
},
"interest": {
  "value": 300,
  "calculation_type": "monthly_fee"
}
```

means:

```text
Fine     → 1.5%
Interest → 3% monthly
```

# Boleto expiration

## `expiration_date`

Defines the boleto expiration date: the last day on which the boleto can be paid.

```json
"expiration_date": "2026-10-30"
```

This should be understood separately from the due date.

```text
due_date
    │
    └── Payment due date

expiration_date
    │
    └── Boleto expiration
```

For example:

```json
"due_detail": {
  "due_date": "2026-08-17"
},
"expiration_date": "2026-10-30"
```

The boleto is due on August 17, while its expiration is October 30.

# Receiving account

## `bank_account_id`

Identifies the bank account that receives the payment of the boleto.

```json
"bank_account_id": "019f0000-1234-5678-9abc-000000000001"
```

This is the bank account that the boleto receivable is issued against, and the one credited when it is paid. It is required.

Always make sure the selected bank account is the account intended to receive the payment. You can list your accounts with [List bank accounts](/v2/api-reference/banking-api/bank-accounts/list-bank-accounts).

# Boleto type

The request contains two fields that define the boleto configuration:

```json
"invoice_type": "invoice",
"wallet_type": "book_entry_electronic_bloquete"
```

These fields determine the type of document and wallet used for the boleto.

Because there are multiple possible values and the correct combination depends on the boleto use case, the complete explanation is maintained in a dedicated guide.

**For details about `invoice_type` and `wallet_type`, open the [Boleto Types](/v2/guides/boleto/boleto-types) guide.**

There you can find:

* available `invoice_type` values;
* available `wallet_type` values;
* what each option represents;
* when each type should be used;
* examples of different boleto configurations.

# Notes

## `notes`

Optional additional information associated with the boleto, up to 3 entries.

Example:

```json
"notes": [
  "Customer reference",
  "Monthly subscription"
]
```

If there are no notes:

```json
"notes": null
```

Use notes for additional information that does not need to be part of the main charge description.

# Other optional fields

## `splits`

Distributes the payment of the boleto among split recipients. Each item names a `counterparty_recipient_id`, a `type` (`percentage` or `fixed`) and a `value` (a percentage from 0 to 100, or a fixed amount in cents).

```json
"splits": [
  {
    "counterparty_recipient_id": "0198aaaa-1111-2222-3333-444444444444",
    "type": "percentage",
    "value": 70
  },
  {
    "counterparty_recipient_id": "0198bbbb-5555-6666-7777-888888888888",
    "type": "percentage",
    "value": 30
  }
]
```

See the [Split payments](/v2/guides/receivables/split-payments) guide for how recipients are created and how the amounts are distributed.

## `options.fee`

Optional boleto settings. `fee` is the fee charged on the payment of the boleto, in cents.

```json
"options": {
  "fee": 0
}
```

See the [Fees](/v2/guides/receivables/fees) guide.

## `merchant`

Merchant to register as the split org merchant. When sent, it is saved.

```json
"merchant": {
  "name": "Merchant Name",
  "tax_number": "12345678000199"
}
```

# Example: complete payment configuration

Suppose you want to create a boleto with:

```text
Amount:              R$ 100.00
Due date:            17/08/2026
Discount:             5% until 16/08/2026
Fine after due date:  1.5%
Interest:             3% monthly
```

The payment rules are:

```json
"due_detail": {
  "due_date": "2026-08-17",
  "discount": {
    "fixed_until_due": {
      "amounts": [
        {
          "value": 500,
          "date": "2026-08-16"
        }
      ],
      "calculation_type": "percentage"
    }
  },
  "fine": {
    "value": 150,
    "calculation_type": "percentage"
  },
  "interest": {
    "value": 300,
    "calculation_type": "monthly_fee"
  }
}
```

The resulting behavior can be understood as:

```text
                    R$ 100.00
                         │
             ┌───────────┴───────────┐
             │                       │
       Pay before due            Pay after due
             │                       │
        5% discount             1.5% fine
             │                  + 3% monthly
             │                     interest
             ▼                       ▼
        R$ 95.00*              Updated amount
```

`*` Assuming the 5% discount applies on the payment date and no other charge applies.

```json
{
  "description": "Mensalidade agosto",

  "external_id": "boleto-demo-2026-001",
  "bank_account_id": "019f0000-1234-5678-9abc-000000000001",
  "counterparty": {
    "name": "Maria Silva",
    "state": "SP",
    "address": "Rua das Flores, 100",
    "city": "Sao Paulo",
    "tax_number": "12345678901",
    "district": "Centro",
    "postal_code": "01001000"
  },
  "expiration_date": "2026-10-30",
  "invoice_type": "invoice",
  "wallet_type": "book_entry_electronic_bloquete",
  "notes": null,
  "due_detail": {
    "due_date": "2026-08-17",
    "fine": {
      "value": 150,
      "calculation_type": "percentage"
    },
    "interest": {
      "value": 300,
      "calculation_type": "monthly_fee"
    },

        "amounts": [
          {

          }

      }
    }
  }

```

In this request:

| Field                | Meaning                                        |
| -------------------- | ---------------------------------------------- |
| `amount`             | Original boleto value: R$ 100.00               |
| `description`        | Description of the charge                      |
| `external_id`        | Internal reference from the client system      |
| `bank_account_id`    | Bank account that receives the payment         |
| `counterparty`       | Payer information                              |
| `due_date`           | Payment due date                               |
| `discount`           | Early-payment benefit                          |
| `fine`               | Late-payment penalty                           |
| `interest`           | Late-payment interest                          |
| `expiration_date`    | Boleto expiration                              |
| `invoice_type`       | Document type                                  |
| `wallet_type`        | Boleto wallet configuration                    |
| `notes`              | Optional additional information                |

For more information about the document and wallet configuration, see the [Boleto Types](/v2/guides/boleto/boleto-types) guide.


The fields worth keeping in your system:

| Field            | Meaning                                                                                           |
| ---------------- | ------------------------------------------------------------------------------------------------- |
| `id`             | Trio ID of the boleto. It is also the ID of its embedded Pix QR code                              |
| `status`         | `created`, `confirmed`, `settled`, `onhold`, `refunded`, `failed` or `cancelled`                  |
| `amount`         | Boleto amount as a money object: `amount` in cents and `currency`                                 |
| `counterparty`   | Payer the boleto is issued to, with the `id` Trio assigned                                        |
| `barcode`        | Barcode of the boleto                                                                             |
| `digitable_line` | Digitable line of the boleto                                                                      |
| `boleto_url`     | URL of the boleto, ready to share with the payer                                                  |
| `due_detail`     | The payment rules as sent. Amount-type rules come back as money objects; percentage rules keep `value` in basis points |
| `issue_date`     | Day the boleto was issued                                                                         |
| `fee`            | Fee charged on the payment, as a money object                                                     |
| `inserted_at`    | When the boleto was created                                                                       |
| `updated_at`     | When the boleto was last updated                                                                  |

A rule configured with `calculation_type: amount` is returned with its `amount` as a money object, for example:

```json
"fine": {
  "calculation_type": "amount",
  "amount": {
    "amount": 150,
    "currency": "BRL"
  }
}
```

# After creation

Every boleto is hybrid: the same `id` identifies its embedded Pix QR code, which you read with `GET /v2/in/pix/qrcodes/{id}`. The [best practices](/v2/guides/boleto/best-practices) guide (in Portuguese) covers the hybrid boleto, its lifecycle and reconciliation.

The boleto itself is managed through these endpoints:

| Operation                                                                                      | Endpoint                               | What it does                                                                                                                     |
| ---------------------------------------------------------------------------------------------- | -------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| [Get boleto](/v2/api-reference/banking-api/receivables/boletos/get)                           | `GET /v2/in/boletos/{id}`              | Returns the boleto with the same fields as the create response                                                                   |
| [Update boleto due date](/v2/api-reference/banking-api/receivables/boletos/update)            | `PUT /v2/in/boletos/{id}`              | Changes the due date. Body: `due_detail.due_date`. Returns `204 No Content`; read the boleto back to see the new due date       |
| [Recreate boleto](/v2/api-reference/banking-api/receivables/boletos/recreate)                 | `POST /v2/in/boletos/{id}/recreate`    | Cancels the boleto and creates a new one with the same fields, the new `amount` and the new due date (or the current one when `due_detail` is omitted). Returns `201` with the new boleto |
| [Cancel boleto](/v2/api-reference/banking-api/receivables/boletos/cancel)                     | `POST /v2/in/boletos/{id}/cancel`      | Cancels the boleto. Returns `204 No Content`                                                                                     |
| [Add protest](/v2/api-reference/banking-api/receivables/boletos/add-protest)                  | `PUT /v2/in/boletos/{id}/protest/add`  | Adds protest to the boleto. Returns `204 No Content`                                                                             |
| [Remove protest](/v2/api-reference/banking-api/receivables/boletos/remove-protest)            | `PUT /v2/in/boletos/{id}/protest/remove` | Removes protest from the boleto. Returns `204 No Content`                                                                      |

To change the due date:

```json
{
  "due_detail": {
    "due_date": "2026-09-17"
  }
}
```

To change the amount, recreate the boleto:

```json
{
  "amount": 15000,
  "due_detail": {
    "due_date": "2026-09-17"
  }
}
```
