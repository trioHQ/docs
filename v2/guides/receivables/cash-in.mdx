title: "Cash in"

---

The term **Cash In** refers to all incoming transactions or deposits into an account — for example, when a Dynamic QR Code is generated and successfully paid.

Now that you are familiar with the core concepts such as QR Codes, Entities, Organizations, and Bank Accounts, you can generate your first Dynamic QR Code using the Trio API.

---

## Before You Start

With your API credentials already generated, we recommend reviewing the API Reference for Dynamic QR Code creation, where all request parameters, attributes, and behaviors are fully documented.

Documentation:

[Create a new dynamic pix QRCode](/v2/api-reference/banking-api/receivables/qrcode-dynamic/post)

To help you get started faster, the example below demonstrates a real Dynamic QR Code creation request using the Sandbox API.

---

## Endpoint

```http
POST https://api.sandbox.trio.com.br/v2/in/pix/qrcodes
```

---

## Request Example

```json
{
  "bank_account_id": "0196346c-ffa2-e861-be85-3c2736d0005f",
  "counterparty": {
    "tax_number": "12385407400",
    "name": "Payer Name"
  },
  "amount": 320000,
  "external_id": "{{$randomUUID}}",
  "description": "Pay in Sandbox",
  "options": {
    "allow_change_the_amount_on_payment": false,
    "show_qrcode_image": false
  }
}
```

### Field Description

- `bank_account_id`: ID of the bank account that will receive the funds. Use the `id` returned by [`GET /v2/bank_accounts`](/v2/api-reference/banking-api/bank-accounts/list-bank-accounts);
- `counterparty`: payer information, including tax number and name;
- `amount`: transaction amount in cents (`10000` = BRL 100.00);
- `external_id`: external transaction identifier used for reconciliation and webhook tracking;
- `description`: transaction description;
- `options.allow_change_the_amount_on_payment`: whether the payer may change the amount. Required in V2;
- `options.show_qrcode_image`: when set to `true`, the API also returns the QR Code image in Base64 format. Required in V2.

Unlike V1, the V2 QR Code response has no `stages`, `virtual_account_id` or `pix_key_id`. Once the QR Code is paid, the deposit shows up as an in document, with its own `status` and `stages`, in [`GET /v2/documents/in`](/v2/api-reference/banking-api/documents/receivables/list-receivables); see the [Document Lifecycle](/v2/guides/pix/document-lifecycle) guide.

## Using Pix Copy and Paste

If the QR Code image was not requested, you can use the `hash` field returned by the API.

This value represents the Pix “Copy and Paste” payload that can be shared directly with the payer.
