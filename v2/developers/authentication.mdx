Trio uses [basic authentication](https://en.wikipedia.org/wiki/Basic_access_authentication) to authenticate the API. You can create `sandbox` and `production` client secret keys in the developer console. We're also offering a company unique identifier to be used as username in the authentication process.

Use your company unique identifier (client\_id) as username and generated secret key (client\_secret) as password to authenticate:

```text
curl https://api.sandbox.trio.com.br/v2/entities \
  -H "Content-Type: application/json" \
  -u {client_id}:{client_secret}
```

Missing or invalid credentials are refused with `401` and the error code `INVALID_CREDENTIALS`. A key that is not allowed to perform the request, for instance a read-only key sending a write, is refused with `403` and `FORBIDDEN`. See the [error table](/v2/developers/error-table).

## Request headers

Besides the authentication, V2 requests carry:

- `Content-Type: application/json` on every request with a body;
- `Trio-Version`: the version of the API the request targets. A request whose header is missing or names a version that is not the current one is refused with `400` and the error code `INVALID_TRIO_VERSION`.

```text
curl https://api.sandbox.trio.com.br/v2/entities \
  -H "Content-Type: application/json" \
  -H "Trio-Version: {trio_version}" \
  -u {client_id}:{client_secret}
```

## Acting on another organization

If your organization has been granted access to another organization, any of your
API keys can operate on it by sending the `Trio-Target-Org-Id` header. This is the
same credential you already use — the header only changes which organization the
request acts on.

<Info>
  Access is granted at the **organization** level (not per key) and is configured
  by the Trio team through a channel. It **cannot** be self-provisioned. Access is
  typically granted automatically to the organizations you create through the
  [Onboarding](/v2/api-reference/banking-api/onboarding/create) endpoint, when your
  channel has API key access enabled: the onboarding response returns the `org_id`
  to send in this header.
</Info>

- **Header omitted** — the request acts on your own organization, exactly as before.
- **Header present** — the request acts on the target organization. The target ID
  is validated against your granted access on every request; if you have no access,
  the request returns `403` with the error code `FORBIDDEN`.

```text
curl https://api.sandbox.trio.com.br/v2/entities \
  -H "Content-Type: application/json" \
  -H "Trio-Target-Org-Id: {target_org_id}" \
  -u {client_id}:{client_secret}
```

<Note>
  If an access is configured as read-only, only `GET`/`HEAD` requests are allowed
  on the target organization. Organizations that require mTLS must be reached over
  your verified channel.
</Note>
