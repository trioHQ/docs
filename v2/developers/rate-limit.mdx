The API enforces rate limits to ensure fair usage and prevent abuse. Respect them to avoid disruptions to your integration.

## Default limits

| Environment | Limit |
| --- | --- |
| `production` | 60 requests per second |
| `sandbox` | 5 requests per second |

The limits apply to each individual account and **to each endpoint**, and are enforced per second.

## When you exceed a limit

The API answers `429 Too Many Requests` with a body that describes the exceeded limit:

```text
HTTP/1.1 429 Too Many Requests
Content-Type: application/json

{
  "error": "Rate limit exceeded",
  "message": "You have reached the maximum allowed requests per second. If you need more bandwidth request to our support team."
}
```

## Back off and retry

When you receive a `429`, back off before retrying:

- retry the request after a short delay;
- use exponential back-off to increase the delay between retries;
- queue requests and spread them evenly over time.

## Higher limits

If your application needs a higher rate limit, you may be eligible for an upgrade. Contact [support](/v2/getting_started/support) to discuss your requirements.
